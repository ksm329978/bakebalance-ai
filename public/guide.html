김교수님, 여기부터 따라 하세요.

이번 주 목표는 화면이 열리는 주소와 숫자를 보내주는 API입니다. 실제 AI와 데이터 저장은 다음 주차 과제입니다.

1. 지금 완성된 화면 확인하기

  1. 대시보드 열기를 누릅니다.
  2. 생산량·판매량·폐기율 카드 3개와 상품 목록 5행이 보이면 화면 확인 완료입니다.
  3. 데이터 주소 열기를 누릅니다. 영어와 숫자가 나오면 정상입니다. 이것이 JSON이라는 데이터 묶음입니다.

이 주소는 현재 본인에게 공개된 개인용 주소입니다. 교수님·동기에게 제출할 ‘누구나 열리는 URL’은 아래 Vercel 방식으로 만들거나, 이 사이트 공유 설정에서 공개 범위를 변경한 뒤 별도 확인해야 합니다.

2. 수업 방식 그대로: Vercel URL 만들기

코드는 완성해 두었습니다. 설치 없이 GitHub 웹사이트에 올릴 수 있습니다.

  1. Vercel 업로드용 코드 ZIP 받기를 누릅니다. 내려받은 ZIP 파일에서 마우스 오른쪽 버튼 → 모두 압축 풀기를 선택합니다.
  2. GitHub에 로그인합니다. 계정이 없으면 Sign up으로 만듭니다.
  3. 새 저장소를 만듭니다. 이름에 bakebalance-ai를 입력합니다. 공개 범위는 Private로 해도 됩니다. README 추가를 선택하고 Create repository를 누릅니다.
  4. 저장소 화면의 Add file → Upload files를 선택합니다. 압축 푼 폴더 안의 모든 파일과 폴더를 끌어 놓습니다. ZIP 자체나 바깥 폴더 한 개를 올리지 않습니다.
  5. 업로드 목록에 package.json, app, data, lib, public이 보이는지 확인하고 Commit changes를 누릅니다. 숨김 .gitignore가 선택되지 않아도 이번 파일에는 비밀 키가 없습니다.
  6. Vercel에 로그인합니다. GitHub로 로그인을 선택하면 연결이 간단합니다.
  7. Add New → Project에서 bakebalance-ai 저장소를 찾아 Import를 누릅니다. 안 보이면 GitHub 연결 권한에서 해당 저장소 접근을 허용합니다.
  8. Framework Preset은 Next.js, Root Directory는 기본값을 유지합니다. Environment Variables는 비워 둡니다. Deploy를 누릅니다.
  9. 성공 화면에서 Visit을 누르고 주소창의 https://…vercel.app 주소를 복사합니다. 끝의 경로나 주소 이름은 Vercel이 정하므로 성공 화면의 실제 주소를 사용합니다.
  10. 휴대폰에서 그 주소를 엽니다. 비로그인 창에서도 열리는지 확인합니다. 로그인 요구가 나타나면 Vercel의 Deployment Protection 설정과 배포 유형을 확인합니다. Production 주소를 사용합니다.

화면 이름과 위치가 바뀌어 찾기 어려우면 해당 화면을 캡처해 보내주세요. 계정 생성·연결은 본인 계정에서 진행합니다.

3. Network 캡처 만들기

  1. 배포한 대시보드를 크롬으로 엽니다.
  2. 키보드 F12를 누릅니다. 안 되면 Fn+F12 또는 Ctrl+Shift+I를 누릅니다.
  3. 오른쪽 패널의 Network 탭을 누릅니다. 안 보이면 » 안에서 찾습니다.
  4. Ctrl+R로 새로고침합니다. 검색칸에 dashboard를 입력합니다.
  5. dashboard 행을 클릭합니다. Headers에서 Status Code: 200이 보이는지 확인합니다.
  6. Win+Shift+S로 화면과 200 표시를 함께 캡처합니다. 직접 관찰한 화면을 제출합니다.

4. 제출물 4개 준비

  1. 배포 URL: 실제 Vercel Production 주소.
  2. PRD v1: PRD 내려받기. Word에 열거나 내용을 복사해 붙여넣고 docx로 저장해도 됩니다. 업로드용 코드에도 같은 문서가 있습니다.
  3. Network 캡처: 직접 확인한 /api/dashboard의 상태 200 화면.
  4. 한 줄 회고: 아래 초안을 실제 경험에 맞게 고칩니다.

    생산·판매·폐기 지표를 카드 3개와 상품 목록으로 정리했고, AI 도움으로 대시보드와 mock API를 구현했다. [내가 실제로 막혔던 단계]는 [실제 해결 방법]으로 해결했다.
