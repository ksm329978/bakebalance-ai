# BakeBalance AI — PRD v1
작성일: 2026-10-14 | AI와 창업혁신 4주차

## 1. 목적
소형 베이커리 점주가 생산·판매·폐기 기록을 다음날 생산계획에 활용하도록 돕는다. 이번 주는 구조와 화면을 확인하는 예시 대시보드다. 공식 자료 Fact Check와 SaaS 설계 검토를 거쳐 아이템은 유지하고 범위를 축소했다. 시장성·추천 정확도·입력시간·지불의향·손실 감소는 현장 검증 대상이다.

## 2. 사용자
타깃: 주요 상품의 생산량을 직접 정하고 일일 기록을 남길 수 있는 독립 베이커리 점주. 초기 실증 공간: 이팝청춘 2호점.
비타깃: 공장 단위 다점포 생산 최적화가 필요한 기업, 판매·생산 기록을 전혀 남길 수 없는 매장.

## 3. 화면
최종 화면 5개: 홈 대시보드 / 매장·상품 설정 / 일일 기록 / 다음날 추천 / 결과 리포트·이용권.
이번 주 홈 대시보드 1개만 구현. 나머지 4개 메뉴는 비활성.
카드 정확히 3개: 생산량 240개 / 판매량 218개 / 폐기율 5.0%.
목록 정확히 1개, 5행: 소금빵·크루아상·단팥빵·모카번·통밀쿠키.
값은 모두 mock JSON에서 가져온다. 폐기율 = 폐기수량 ÷ 생산수량 × 100. 잔량은 폐기와 분리한다.

## 4. 데이터
이번 주 data/dashboard.json. storeName, date, isMock, totals(produced,sold,waste,remaining), recent(id,name,produced,sold,waste,remaining,planned,reason,status).
각 행의 생산 = 판매 + 폐기 + 잔량. 전체 합계는 각 행 합계와 일치.
향후 테이블 7개 이하: users, stores, store_members, products, daily_records, recommendations, subscriptions. 이번 주 DB 생성 안 함.

## 5. 외부 API
이번 주 0개. GET /api/dashboard는 같은 서비스 내부 API다. 5주차 이후 LLM API 1개 검토. POS·날씨·결제 연결 없음.

## 6. 흐름
접속 → 로딩 문구 → GET /api/dashboard → lib/dashboard-data.ts의 getDashboard() → JSON 응답 → 카드·목록 표시.
실패하면 오류 문구와 다시 시도 버튼. 데이터는 서버 함수에서 제공. 6주차에 함수 내부를 DB 조회로 교체.

## 7. 제외 범위
로그인·회원가입, DB, 실제 기록 입력·저장, 실제 AI 호출, 자동 추천, 결제, POS 연동, 차트, 검색, 추가 대시보드 화면. 사용 안내와 PRD는 과제 참고 문서다.

## 8. 완료 기준
URL에서 한국어 대시보드 표시. 카드 3개·목록 1개·상품 5행. 비활성 메뉴 4개. 모든 숫자와 상품 목록이 API 응답 기반. /api/dashboard 상태 200. 로딩·실패 상태 존재. 좁은 화면에서 카드 3개가 보이고 표는 가로 스크롤. 빌드 성공.

## 정의서 보완
과금: 매장 1곳의 1개월 이용권 1건(가격은 가설).
1건당 원가: 이번 주 AI 호출 0원. 유료 운영 시 서버·DB·지원·LLM 비용 실측 필요. 호스팅 비용이 영구 무료라는 뜻은 아님.
승인: 점주가 생산계획 최종 승인. 추천만 제공하며 실제 생산 자동 실행 없음.
탈락 조건 7개: 실시간 채팅·영상, 배송·정산 커머스, 전용 앱·HW, 의료·금융 민감정보, 양면 매칭, 금지 크롤링, 외부 플랫폼 승인 의존 모두 현재 MVP 제외.
5주차 AI가 만들 한 가지: 누적 생산·판매·폐기·품절을 근거로 한 권장 생산량의 설명. 숫자 산출의 성능 검증은 별도로 수행.

## 추가 체험 화면 업데이트
사용자 요청에 따라 메뉴 5개를 모두 개방. 홈은 과제용 mock 유지. 설정·기록은 localStorage에 브라우저별 저장, 수량 검증 및 CSV 내보내기. 추천 화면은 최근 저장일 판매량을 생산단위로 올림한 규칙 계산이며 AI 아님. 리포트는 저장된 기록 합계. 실제 DB·AI·결제는 연결 안 됨. 공개 방문자의 입력은 서로 공유하지 않음.
