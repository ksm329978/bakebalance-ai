# BakeBalance AI — PRD v1.1 (5주차)
작성일: 2026-10-17 | AI와 창업혁신 | 기존 구현 및 AI 연결 실습 반영

## 1. 목적
소형 베이커리 점주가 생산·판매·폐기 기록을 다음날 생산계획에 활용하도록 돕는다. 이번 주는 구조와 화면을 확인하는 예시 대시보드다. 공식 자료 Fact Check와 SaaS 설계 검토를 거쳐 아이템은 유지하고 범위를 축소했다. 시장성·추천 정확도·입력시간·지불의향·손실 감소는 현장 검증 대상이다.

## 2. 사용자
타깃: 주요 상품의 생산량을 직접 정하고 일일 기록을 남길 수 있는 독립 베이커리 점주. 초기 실증 공간: 이팝청춘 2호점.
비타깃: 공장 단위 다점포 생산 최적화가 필요한 기업, 판매·생산 기록을 전혀 남길 수 없는 매장.

## 3. 화면
현재 메뉴 6개: 홈 대시보드 / 매장·상품 설정 / 일일 기록 / 다음날 추천 / 결과 리포트·이용권 / 음료 재고·발주.
기존 화면을 유지하고 홈 안에 ‘AI 운영 분석’ 영역 1개를 추가한다. AI 전용 새 메뉴는 추가하지 않는다.
- 분석 자료 선택: ‘수업 실습용 MOCK 데이터’ 또는 ‘현재 대시보드 데이터’.
- 실행: ‘AI 분석하기’ 버튼 1개. 실행 중 중복 클릭을 막고 로딩 안내를 표시한다.
- 결과: Gemini가 반환한 한국어 운영 분석, 자료 종류, 기준 날짜, 모델명, 분석 시각 표시.
- 분석 내용: 전체 요약 / 상품별 관찰 / 다음 운영일 실행 제안 / 자료 한계. 고정된 주제 카드 3개 형식은 사용하지 않는다.
- 실패: 키 설정, 인증·요청 설정, 모델, 사용 한도, 빈 응답, 연결 오류 등의 안내 표시. 실패 결과를 실제 AI 분석으로 표시하지 않는다. 실패 시 가상 분석 결과로 자동 대체하는 기능은 이번 구현에 포함하지 않는다.
기존 핵심 카드 3개(생산량·판매량·폐기율), 상품 현황 표를 유지한다. 상품 5종은 쿠키·베이글·휘낭시에·레몬 마들렌·초코 마들렌이다. 휴대폰에서는 분석 조작 영역을 세로로 배치하고 표는 가로 스크롤한다.

## 4. 데이터
실습 데이터: data/dashboard.json. storeName, date, isMock, totals(produced,sold,waste,remaining), recent(id,name,produced,sold,waste,remaining,planned,reason,status).
가상 데이터 합계: 생산 240개, 판매 218개, 폐기 12개, 잔량 10개. 판매율 약 90.8%, 폐기율 5.0%.
각 행의 생산 = 판매 + 폐기 + 잔량. AI API는 상품별 수량을 검증하고 합계를 다시 계산한다.
‘수업 실습용 MOCK 데이터’는 서버의 고정 JSON을 사용한다. ‘현재 대시보드 데이터’는 화면에 표시된 기록을 전달하며, 저장 기록이 없으면 예시 데이터를 사용한다.
일일 기록·매장 설정·음료 재고 등 기존 입력은 브라우저 localStorage에 저장한다. AI 결과는 현재 화면 상태에 보관하며 새로고침·화면 전환 시 유지하지 않는다. 기기 간 자동 동기화 및 공유 DB는 없다.
향후 테이블 7개 이하: users, stores, store_members, products, daily_records, recommendations, subscriptions. 이번 주 DB 생성 안 함.

## 5. 외부 API
외부 AI 서비스는 Gemini 1개를 사용한다. 실제 호출은 서버 app/api/analyze/route.ts에서 수행한다. GET /api/dashboard와 POST /api/analyze는 같은 서비스 내부 API다.
- 서버 비밀 설정: GEMINI_API_KEY. Vercel의 Production 환경 변수로 저장한다.
- 모델 설정: GEMINI_MODEL. 생략 시 코드 기본값 gemini-3.8-flash를 사용한다.
- 로컬 실행이 필요한 경우 프로젝트 루트의 .env.local에 같은 변수명을 사용한다. 키 실제 값은 PRD·화면·GitHub에 포함하지 않는다.
- 수업 예시의 LLM_API_KEY·LLM_MODEL은 개념상 같은 역할이지만 현재 코드의 변수명과 다르므로 그대로 대체하지 않는다.
분석 버튼을 누를 때만 호출한다. POS·날씨·결제 API 연결은 없다.

## 6. 흐름
기존 흐름: 접속 → GET /api/dashboard → getDashboard() → JSON → 저장 기록·설정 반영 → 카드·표 표시.
AI 흐름: 자료 선택 → AI 분석하기 → POST /api/analyze → 입력 검증 및 합계 재계산 → 서버에서 Gemini 호출 → 응답 텍스트 확인 → 대시보드에 분석 결과 표시.
MOCK 선택 시 서버 고정 데이터를 사용하고, 현재 대시보드 선택 시 해당 화면의 데이터를 사용한다. 자료 선택 또는 화면 데이터 변경 시 이전 결과를 지워 서로 다른 자료의 결과가 섞이지 않도록 한다.
오류 시 안내 문구를 표시하고 사용자가 다시 실행할 수 있다. 키를 저장·변경한 뒤에는 Vercel 재배포로 반영한다.
기존 ‘다음날 추천’의 조건별 수량 계산과 Gemini의 서술 분석은 구분한다. Gemini 결과가 생산계획이나 실제 발주를 자동 변경하지 않는다.

## 7. 제외 범위
로그인·회원가입, 공유 DB, 기기 간 기록 동기화, AI 분석 결과의 영구 저장, 이미지 생성, 자유 질문 채팅, POS 연동, 실제 결제·이용권 과금, 실제 발주 전송, 자동 생산 실행, 추천 정확도 보장, 실제 수요·수익 예측 모델은 제외한다.
기존 브라우저 기록 입력·저장, CSV 내보내기, 조건별 생산계획 및 음료 재고·발주 계산은 유지한다. 실제 AI 호출은 이번 주 포함 범위로 전환한다.
하루 데이터로 장기 추세를 단정하지 않는다. 가격·원가·재료 재고가 없는 경우 매출·이익·재료 발주량을 생성하지 않도록 AI에 지시한다. 생산·발주 결정은 담당자가 검토한다.

## 8. 완료 기준
1. 기존 메뉴 6개와 생산·판매·폐기 카드, 상품 5행, 기록·재고 기능이 유지된다.
2. GET /api/dashboard가 JSON 데이터를 반환한다.
3. MOCK 데이터 선택 후 분석 버튼을 누르면 서버가 Gemini를 호출하고 실제 응답 및 자료 종류·모델·시각을 표시한다.
4. 현재 대시보드 자료도 선택 가능하며 예시와 저장 기록을 구분한다.
5. 로딩·중복 클릭 방지·오류 표시가 있고 오류를 성공으로 표시하지 않는다.
6. 키 실제 값이 화면·공개 코드·PRD에 포함되지 않는다.
7. PC 및 휴대폰에서 대시보드와 AI 분석 결과를 확인할 수 있다.
8. 배포용 빌드와 TypeScript 검사를 통과한다.

확인 현황(2026-10-17): 배포용 빌드·TypeScript 검사와 모의 응답 기반 API 오류 분기 검사를 통과했다. PC의 실제 Gemini 분석 결과 화면을 확인했고, 휴대폰 결과 표시는 사용자 확인을 받았다. 배포 후 모든 기존 입력 기능 및 모든 오류 상황을 다시 전수 검사한 것은 아니다. 키 비노출은 구현 구조에서 확인했으며 배포 자산 전체 보안 감사 완료를 뜻하지 않는다.

## 정의서 보완
과금: 매장 1곳의 1개월 이용권 1건(가격은 가설). 실제 결제는 미구현.
1건당 원가: Gemini 모델·요금제·사용량에 따라 달라진다. 서버·지원·LLM 비용 실측이 필요하며 영구 무료를 가정하지 않는다.
승인: 점주가 생산계획을 최종 승인한다. 제안만 제공하며 생산·발주를 자동 실행하지 않는다.
탈락 조건 7개: 실시간 채팅·영상, 배송·정산 커머스, 전용 앱·HW, 의료·금융 민감정보, 양면 매칭, 금지 크롤링, 외부 플랫폼 승인 의존은 현재 MVP 제외.
이번 주 AI가 만드는 것: 전달된 생산·판매·폐기·잔량에 근거한 운영 분석과 다음 운영일 검토 제안. 수량 예측 정확도는 별도 검증 대상이다.
